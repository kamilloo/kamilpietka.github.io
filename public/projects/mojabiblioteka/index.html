Moja Biblioteka

A local-first Flutter application for cataloguing books, tracking lending and managing a personal library with barcode-based book discovery.

FlutterDartSQLiteOpen Library
Live product ↗ Source ↗

Overview

Moja Biblioteka supports book cataloguing, search, reading status and lending history. Its local-first approach keeps everyday library management independent of a continuously available hosted backend.

Architecture and offline behavior

Flutter UI → application logic → on-device SQLite storage. ISBN and barcode discovery can request metadata from Open Library, while manual entry and local library access remain available offline. Remote cover images still require connectivity and use placeholders when unavailable.

Implementation and data management

The source documents UUIDs and timestamps, book details, lending and return flows. Open Library title or author searches are explicit requests, not requests on each keystroke. Selecting a result prefills the form without saving a book. Work-level search results do not supply an assumed physical-book ISBN; users can enter or scan the actual identifier.

Engineering decisions and privacy

Local storage reduces dependency on a remote service for core workflows. External metadata lookup remains a separate network operation. The privacy policy describes primarily on-device storage; local-first does not mean every integration is offline. Cross-device synchronization would need its own conflict and privacy model.

Testing and product delivery

Repository documentation defines formatting, static analysis, unit and widget tests, followed by a debug Android build in CI. SQLite regression and Android release documents track migration safety, signing and device QA. The product website and privacy pages support delivery preparation; this case study does not claim app-store approval or completed physical-device release testing.

Outcomes and lessons

The project connects local persistence, optional metadata discovery and release documentation in a single product. A useful offline experience requires clear boundaries: local records remain usable, while missing network metadata does not prevent manual cataloguing.
