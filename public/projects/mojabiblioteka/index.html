A local-first personal library application for cataloguing books, tracking lending, and discovering book information through ISBN and barcode scanning.

Visit product website ↗ Explore source code ↗

The problem

Managing a personal library should be useful even when network access is unavailable. The application aims to make book cataloguing, lending history, and reading status convenient without depending on a continuously available backend.

Engineering approach

  • Local-first persistence: Flutter/Dart application with an on-device SQLite data store.
  • Book discovery: ISBN and barcode scanning combined with Open Library metadata integration.
  • Library workflows: Book collection, reading status, and lending history.
  • Delivery: Consideration of privacy, release preparation, and a public-facing product website.

Architecture at a glance

Flutter UI → application logic → local SQLite storage

For supported discovery flows, the app integrates external book metadata from Open Library. The local database keeps the core library experience available offline.

Key trade-off

A local-first design reduces the dependency on a hosted backend for everyday book management. It also means that device-to-device synchronization, if added later, needs an explicit conflict-resolution and privacy model rather than being assumed to work automatically.
