AWS Data Engineering Labs

Two AWS data pipelines exploring different processing models: batch analytics and real-time event processing.

Overview

These learning labs compare query-oriented batch processing with event-driven aggregation. Their scope is service composition and data movement, rather than a measured production workload.

Batch architecture: ETL and ELT

Raw input lands in Amazon S3. The ELT-style demo queries raw data and applies SQL transformations with Athena. The ETL demo uses AWS Glue to clean and transform data into processed S3 output. This extends the homepage’s S3 → Glue → Athena overview with the separate raw-query path documented in the repository.

Streaming architecture

Event producer → Kinesis stream → Lambda → DynamoDB. The lab configures an event-stream with one shard and a Python ProcessEvents function. EventCounts stores results with action as its string partition key; sample click and purchase events exercise the flow.

Service selection and trade-offs

S3 retains datasets for query and transformation workflows. Athena supports SQL analysis without a separate application query service, while Glue provides a dedicated transformation step. Kinesis and Lambda instead process incoming events and persist action counters in DynamoDB. Batch tolerates waiting for dataset processing; streaming introduces event delivery and retry concerns. No measured latency comparison is available.

Validation and infrastructure considerations

The streaming instructions verify processing through CloudWatch logs and increasing DynamoDB counters. Batch instructions run the supplied queries and scripts after uploading raw files. These are documented manual checks, not an automated test report. The example DynamoDB permission uses Resource: *; resource-scoped IAM and a review of retry and duplicate-event handling are needed before production use.

Outcomes and lessons

The labs demonstrate distinct persistence and processing models using managed AWS services. Service selection follows the required result: querying datasets or reading event aggregates. Production scale, cost, delivery guarantees and automated infrastructure deployment are not established by the available evidence.
